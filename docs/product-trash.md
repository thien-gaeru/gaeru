# Product trash and inventory actions

- Catalog → Products now separates the current catalog and Deleted products. The inventory list offers the same move-to-trash action for the entire product, across variants and warehouses. The confirmation states that scope explicitly. The action hides catalog/inventory listings without reducing or erasing physical stock.
- Restore returns a product to draft. Restore & activate makes it public using the remembered saleable variant flags. New moves to trash save those flags before disabling variants. Older deletions have no snapshot: restore as draft or edit the intended variant flags before activating; the system does not guess which old variants should be sold.
- Editing a deleted product uses an explicit trash workspace. Saves keep the parent deleted and all live variant flags disabled, while retaining the intended activation selection separately. Existing IDs, stock history and links remain intact; adding variants also records their intended flags. Stale normal editors cannot resurrect a deleted product. The publish button is absent in the trash editor.
- Permanent deletion is available to owner/admin with catalog.write, CSRF protection, current product version and typed slug confirmation. It only deletes a trashed catalog entry with zero aggregate/warehouse stock and no order-item, stock-movement, allocation, purchase-item or receipt-item references. Other records remain in trash with a clear explanation. A foreign-key race fails safely. The immutable audit survives; conversation names/messages survive while their product reference becomes null. Shared media is retained.
- A product with historical operations can be restored or edited; permanently deleting its accounting/inventory history is not part of this feature.

White product-image canvases blend automatically with the light card background via scoped multiply compositing, including new uploads and editor previews. Stored images are not rewritten, so text, logos and original details remain intact. Dark promotional cards keep their existing rendering. Complex colored backdrops are not automatically extracted.

The redundant footer staff-status control is removed from chat. Direct staff requests remain in the attachment/action menu and the inline handoff response. The note/greeting uses the selected enabled provider (GPT/OpenAI, Gemini or Claude), reports disabled/unconfigured/unknown states, and reflects human handling and closed threads. Active polling refreshes provider configuration at most once per minute; it does not assert that a saved key has passed the separate compatibility test.

Validation: real PostgreSQL-compatible integration tests exercise trash visibility, edited snapshots, stale requests, draft restoration, activation, legacy deletion fallback, zero-stock history blocks, owner/admin purge, manager/viewer denial, CSRF, shared chat retention and permanent removal of an unused product. Browser fixtures verify inventory cancel/delete, trash editing, typed-slug guard cancellation, mobile actions, stock restored with the same quantity, image compositing after scroll, and disabled/Claude chat disclosures. Only generated local fixtures are changed during browser tests. Production records are not deleted, restored or edited by this task.
