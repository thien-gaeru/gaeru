# Unified image quality, cache and product description canvas

All image upload routes (product/gallery/variant/description, article cover, marketing banner and chat image) call storeUpload and the same Sharp encoder. Static PNG/JPEG/WebP inputs are fully decoded, EXIF orientation is applied, metadata stripped and colors converted to sRGB; output is WebP quality 90, alpha quality 100, effort 5, at most 1600 pixels per edge, never upscaled or stretched. Existing in-bounds WebP without metadata is retained byte-for-byte to avoid repeat lossy encoding. Alpha remains intact. Upload limits remain 8 MB product, 5 MB cover/banner and 10 MB chat, with a 24 MP input guard. Animated images are rejected; HEIC requires the installed decoder and otherwise produces a clear conversion-to-JPG instruction. Documents and videos keep their original bytes. Chat image filename/MIME and logical quota follow the converted file.

An in-process image LRU stores exact verified bytes, not lower-quality versions: 64 MB total, 8 MB per entry, 5-minute TTL, 16 in-flight unique loads maximum. Concurrent requests for the same immutable pointer share a read. Errors and oversized payloads are not cached. Only product/news/banner namespaces use the cache; chat files and videos bypass it. Database publication/ownership checks still run before retrieving any cached bytes. MEDIA_CACHE_ENABLED=false disables the memory cache. No service worker or public shared cache is introduced for private data.

Published news images add ETag/private 60-second browser revalidation, matching product image policy. Admin/private chat responses remain no-store. Public HTML/text assets use standard compression, excluding account/admin/private API routes. Versioned public CSS/JS/fonts/images receive immutable year-long cache headers; every changed public asset reference is version-bumped. HTML is revalidated; account.js remains no-store. Product main images are eager/high priority; deferred images decode asynchronously. Future updates to versioned asset contents must bump their URL version.

The description editor is one bounded canvas with a fixed toolbar and count. Textareas grow into the canvas so long text does not create nested scrollbars. Text and images stay in the existing escaped plain-text/descriptionMedia schema. A dedicated handle reorders using Pointer Events, with edge auto-scroll; pointer cancellation restores order. Alt+arrow and existing up/down buttons provide keyboard/mobile alternatives. Bold uses the existing safe **text** syntax. Count and backend limits remain enforced; no arbitrary HTML is stored. Sorting reuses the existing paragraph-position representation, preserving captions, canonical media IDs and optimistic version checks.

Verification covers all image scopes, transparency, orientation/metadata removal, no repeated WebP compression, caching byte limits/expiry/dedup/failures, browser cache/compression/privacy headers, revoked-image conditional reads, drag/cancel/keyboard ordering with persisted text/captions, and existing catalog/stock/security flows. A real G1 source sample retained 1254x1254 dimensions while shrinking from 1,630,342-byte PNG to 72,092-byte WebP. This is a file-conversion example, not a measured page-speed guarantee. Browser visual/mobile gesture QA remains unavailable while local browser use is disabled in Work settings.
