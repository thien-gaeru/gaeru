# Unified image quality, cache and product description canvas

Product/gallery/variant/description, article cover and marketing banner uploads use `storeUpload`; the file library uses the same Sharp encoder. New still images keep their full dimensions and are encoded as **lossless WebP**, alpha quality 100, effort 5. EXIF rotation is applied, metadata stripped and colour normalized to sRGB. The lossless guarantee applies to **visible RGB detail and alpha in the decoded 8-bit sRGB image**, not to arbitrary original file metadata, wide-gamut profiles or a JPEG's previously discarded information. RGB values hidden behind completely transparent pixels may be normalized by WebP; exact source bytes remain in the protected original. Higher-depth images are rejected explicitly rather than silently reduced to 8-bit. Existing metadata-free WebP is fully decoded for validation and retained byte-for-byte, including larger images; it is not re-encoded to pretend to recover prior lossy detail.

Input limits remain 8 MB product/library images and 5 MB covers/banners. Image processing is bounded to 24 MP and 16,383 pixels per edge (WebP's format limit). Encoded output has a separate 25 MB storage ceiling because lossless WebP can exceed a compressed JPEG's file size. Exceeding the output ceiling returns 413 `IMAGE_OUTPUT_TOO_LARGE`; the encoder does not silently resize or lower quality. There are at most two active request slots and eight waiting requests. Within those slots, a 24 MP weighted decode budget serializes larger work; optional cutout pixels count three times because the mask and flood-fill queue need extra memory. Both queues reserve capacity before waking a waiter and release it on failure. This bounds work, not total process RAM; local generated-fixture memory measurements and production capacity checks must be reported separately. HEIC still requires the installed decoder; corrupt, mismatched and animated input is rejected.

Persistent public/library uploads retain the exact original bytes separately through `media_upload_originals`; originals remain protected by authenticated library access. Optional product background removal only removes nearly white regions connected to the border, preserves enclosed white details and encodes the full-size cutout losslessly. It is a conservative white-background heuristic, not semantic AI segmentation. It skips the optional cutout above 8 MP to bound pixel-mask memory, keeping the full-size image instead. Complex or nonwhite backgrounds require reviewed editing. No existing production image is regenerated by this change.

Chat/care attachments initially retain their source bytes so sending is not blocked by image encoding. The chat worker applies the same optional image encoder within the 24 MP guard and only replaces the displayed file if WebP is smaller. Unsupported/oversized images remain usable in their original form; the source remains separately available under the existing authorization/retention rules. Documents and videos retain source bytes; optional compression must not be described as unlimited capacity or guaranteed video transcoding.

An in-process image LRU stores exact verified bytes, not lower-quality versions: 64 MB total, 8 MB per entry, 5-minute TTL, 16 in-flight unique loads maximum. Concurrent requests for the same immutable pointer share a read. Errors and oversized payloads are not cached. Only product/news/banner namespaces use the cache; chat files and videos bypass it. Database publication/ownership checks still run before retrieving any cached bytes. MEDIA_CACHE_ENABLED=false disables the memory cache. No service worker or public shared cache is introduced for private data.

Published news images add ETag/private 60-second browser revalidation, matching product image policy. Admin/private chat responses remain no-store. Public HTML/text assets use standard compression, excluding private API/admin-page responses. Reviewed admin CSS/JS can compress while remaining no-store. Versioned public CSS/JS/fonts/images receive immutable year-long cache headers; every changed public asset reference is version-bumped. HTML is revalidated; account.js remains no-store. Product main images are eager/high priority; deferred images decode asynchronously. Future updates to versioned asset contents must bump their URL version.

The description editor is one bounded canvas with a fixed toolbar and count. Textareas grow into the canvas so long text does not create nested scrollbars. Text and images stay in the existing escaped plain-text/descriptionMedia schema. A dedicated handle reorders using Pointer Events, with edge auto-scroll; pointer cancellation restores order. Alt+arrow and existing up/down buttons provide keyboard/mobile alternatives. Bold uses the existing safe **text** syntax. Count and backend limits remain enforced; no arbitrary HTML is stored. Sorting reuses the existing paragraph-position representation, preserving captions, canonical media IDs and optimistic version checks.

Current regression tests cover full-size fine-colour/partial-alpha pixel equality, decoded JPEG equality after EXIF rotation, exact reuse of existing large WebP, corrupt WebP rejection, output ceilings, higher-depth rejection, bounded parallel work, full-size cutouts and protected original bytes. Chat tests cover deferral and retaining a smaller original instead of a larger conversion. Responsive 480/800/1200 display renditions remain separate from full-size uploads and retain their existing authorization and cache rules. These are local correctness checks; release/browser/provider verification is recorded separately in the dated acceptance report. Lossless upload conversion alone is not a measured page-speed guarantee.
